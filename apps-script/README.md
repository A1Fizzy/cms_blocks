# Публикация «Полки» в Google Apps Script

Нужен только ваш Google-аккаунт. Vercel, Python, база SQLite и платный хостинг для этой версии не нужны.

## 1. Создайте проект

1. Откройте https://script.google.com/ и нажмите «Новый проект». Назовите его «Полка».
2. Замените содержимое `Код.gs` (Code.gs) содержимым файла `apps-script/Code.gs` из этого репозитория.
3. Нажмите «+» рядом с «Файлы» → HTML. Назовите файл `Index` и замените его содержимое файлом `apps-script/Index.html` целиком. Это готовая сборка интерфейса; остальные HTML/CSS/JS файлы загружать не нужно.
4. В настройках проекта включите показ файла манифеста `appsscript.json`. Вернитесь в редактор и замените его содержимое файлом `apps-script/appsscript.json`.
5. Сохраните проект.

## 2. Подготовьте хранилище

1. В списке функций редактора выберите `setup` и нажмите «Выполнить».
2. Разрешите проекту доступ к вашему Google Диску и адресу аккаунта. Это требуется для сохранения библиотеки и проверки владельца. Приложение запрашивает доступ к Диску; используйте только собственный проект с проверенным кодом. Если Google показывает предупреждение о непроверенном приложении, убедитесь, что это именно созданный вами проект.
3. После успешного выполнения на Диске появится папка «Полка — CMS блоки» с файлом `library.json`. Начальные направления уже созданы. Повторный `setup` не стирает данные.

## 3. Опубликуйте

1. Нажмите «Развернуть» → «Новое развертывание» → тип «Веб-приложение».
2. «Запуск от имени»: **Я**.
3. «У кого есть доступ»: **Только я**. Не выбирайте доступ для всех или всех пользователей Google.
4. Нажмите «Развернуть» и откройте выданный URL веб-приложения под тем же аккаунтом.
5. Сохраните URL в закладки. Эта ссылка и есть ваш сервис.

Настройки доступности могут ограничиваться администратором Google Workspace. Сервер дополнительно сравнивает адрес текущего пользователя с владельцем и запрещает доступ при пустом адресе. При отказе войдите под владельцем и проверьте параметры развертывания; не убирайте проверку доступа.

## 4. Проверьте

Добавьте направление, создайте блок с `<h2>Привет</h2>` в HTML и `h2 { color: green; }` в CSS. Проверьте зелёный заголовок в предпросмотре. Сохраните, перезагрузите страницу, откройте блок и скопируйте оба поля. Если браузер ограничивает буфер обмена внутри Google iframe, выделенный текст можно скопировать Ctrl+C / ⌘C. Удалите тестовый блок и направление. Под другим аккаунтом доступ должен быть закрыт.

## Обновления, хранение и ограничения

- После изменения кода: «Развернуть» → «Управление развертываниями» → карандаш → «Новая версия» → «Развернуть». URL останется прежним. Само сохранение кода не обновляет опубликованную версию.
- Не удаляйте файл `library.json` и свойства скрипта `OWNER_EMAIL`, `LIBRARY_FILE_ID`. Не открывайте общий доступ к папке и проекту. Резервная копия — скачанный `library.json` или копия файла на Диске. Для восстановления содержимого замените текст исходного файла валидным JSON из копии, сохранив его ID.
- Вся библиотека хранится одним JSON-файлом; таблица не используется. Лимиты этой версии: 500 000 символов HTML+CSS на блок и 5 млн символов на библиотеку. Чтение и запись обращаются к Google Диску и могут занимать несколько секунд. Действуют также квоты Apps Script вашего аккаунта.
- Запись защищена блокировкой, но при одновременном редактировании одного блока в двух вкладках последнее сохранение заменяет предыдущее.
- Предпросмотр запрещает JavaScript и изолирует стили. Внешние HTTPS-изображения и шрифты могут загружаться. Окружение и стили вашей CMS могут менять конечный вид блока.
- Существующая локальная SQLite-библиотека не переносится автоматически. Локальная версия остаётся в репозитории отдельно.

## Для разработки

Общий интерфейс находится в `static/`. После его изменения выполните `python tools/build_apps_script.py`, чтобы обновить `apps-script/Index.html`. Проверка серверной логики с имитацией Google API: `node --test tests/test_apps_script.cjs`. Локальные тесты не проверяют реальные разрешения Google, квоты и публикацию — проверку из раздела 4 нужно пройти после развертывания.

## Атрибуты Метрики по направлениям

Кнопка «Показать атрибуты» открывает редактируемую текстовую памятку выбранного направления. Укажите названия кнопок и идентификаторы целей, затем нажмите «Сохранить список». Для «Статьи» по умолчанию показаны три примера целей шапки; после сохранения используется ваш текст, включая пустой список. Списки других направлений изначально пустые. Сервис не устанавливает цели на элементы CMS автоматически.

Для обновления уже работающего приложения замените **Code.gs** и **Index.html**, затем выпустите новую версию существующего развертывания. Повторно выполнять setup или создавать хранилище не нужно; существующие блоки сохраняются.
